# Event log — Semiconductors (Step 1, Track 2)

Curated event records for the 5 categories declared in
`docs/prereg_step1_semis.docx` §3 and `sectors/semis.yaml`. Mirror della
struttura `data/events/ai_infra/` con adattamenti settore-specifici.

## ⚠️ Binding constraints (prereg §11 + ADR 0005)

Before editing any file in this directory:

- **DO NOT** add events whose announcement date is after the start of data
  collection for the run in progress (anti-pattern: post-hoc event
  fishing).
- **DO NOT** modify the schema columns. The pydantic schema and the panel
  builder rely on these exact names.
- **DO NOT** add new categories or merge categories. Step 1 tests exactly
  five hypotheses (A-E); changing the count invalidates the BH correction.
- **DO NOT** edit `earnings.csv` by hand. It is regenerated automatically
  from `fetch_earnings` (yfinance + SUE computation per prereg §3.1).
- **DO NOT** pool events with Sector 1 (`data/events/ai_infra/`). Each
  Track has its own independent statistical test (ADR 0005 isolation rule).

## ⚠️ Naming caveat (historical from Sector 1)

I file `ppa.csv` e la colonna `xlk_t1_return` in `shocks.csv` portano nomi
che riflettono il **primo settore implementato (AI Infra)** dove cat B
erano power purchase agreements e cat D usava XLK come benchmark
sector-shock proxy. Per Semis:

- `ppa.csv` contiene di fatto **hyperscaler design wins** (es. "NVDA selected
  by META for $X-billion deal"). Il nome file è mantenuto per
  compatibilità con il code path hard-coded in `panel.py:43`.
- La colonna `deal_mw` in `ppa.csv` è semanticamente irrilevante per Semis
  (i design wins non si misurano in MW). **Lasciare sempre vuota** la
  colonna `deal_mw`: il code (`panel.py:111`) farà fallback a magnitude=1.0
  (binary), che è il `magnitude_metric: binary` dichiarato nello YAML
  Semis per cat B. Il deal value reale va in `deal_value_usd` per
  reference manuale (non letta dal panel builder ma utile per il
  curatore).
- La colonna `xlk_t1_return` in `shocks.csv` è **calcolata a runtime** dal
  CLI (`cli.py:_fill_d_magnitudes`) usando il `benchmarks.primary` del
  settore corrente. Per Semis usa quindi SOXX T+1 return, non XLK. **Lasciare
  vuota** la colonna nel CSV: viene popolata in pipeline.

Questi due naming legacy non rompono la pipeline ma sono cognitivamente
fragili. Refactoring (rename a `magnitude_optional` e `bench_t1_return`) è
deferred a un futuro ADR; tracked nei `open_questions` di
`sectors/semis.yaml`.

## Schema reference

### `earnings.csv` (auto)
```
ticker, announcement_date, fiscal_quarter, estimate_eps, actual_eps,
sue, has_consensus, surprise_sign
```
SUE per prereg §3.1: `(actual − estimate) / std(estimate over previous 8 quarters)`.
Threshold for event qualification: `|SUE| > 1.0`.

### `ppa.csv` (manual, cat B = design_win)
```
ticker, announce_date, counterparty, deal_mw, deal_value_usd, source_url, note
```
- `counterparty`: one of `MSFT, META, AMZN, GOOGL, ORCL` (prereg §3.2 hyperscaler list, identica a Sector 1).
- `deal_mw`: **lascia vuoto** per Semis (vedi caveat sopra).
- `deal_value_usd`: optional, deal size in USD for curator reference. NOT read by panel builder for cat B (binary magnitude).
- `source_url`: REQUIRED — link diretto al press release / filing.
- `note`: free text (es. "NVDA H200 cluster order", "via subsidiary X").

### `orders.csv` (manual, cat C = capacity_order_intake)
```
ticker, announce_date, deal_value_usd, backlog_change_pct, source_url, note
```
- Threshold prereg Semis §3.3: `deal_value_usd > $1B` OR `backlog_change_pct > 10%`.
  (Semis ha threshold più alta di AI Infra dove era $100M.)
- Tipici eventi: TSM Arizona Phase expansion, MU Idaho fab, Intel-AMAT
  $X-billion contract, NVDA Blackwell pre-orders disclosed.
- `deal_value_usd`: USD value (numeric). Use raw dollars (es. `1500000000` per $1.5B).
- `backlog_change_pct`: fractional change (es. `0.15` per +15%). Use only if disclosed as % delta.

### `shocks.csv` (manual, cat D = sector_shock)
```
event_date, event_type, description, xlk_t1_return, source_url
```
- NO `ticker` field — broadcast to all 8 tickers of universe on the event date.
- `event_type`: free-text tag for categorization (e.g., `bis_export_controls`,
  `china_retaliation`, `geopolitical_conflict`, `supply_chain_disruption`).
- `xlk_t1_return`: **lascia vuoto** — runtime fill da SOXX (vedi caveat sopra).
- Tipici eventi: BIS Oct 2022 rules, BIS Oct 2023 update, BIS Dec 2024 HBM
  rules, BIS Jan 2025 AI Diffusion Framework, Trump Dec 2025 H200 reversal,
  China retaliation announcements.

### `analyst.csv` (manual, cat E = analyst_rating)
```
ticker, event_date, bank, action, old_target, new_target, target_change_pct, source_url
```
- `bank`: must be in `tier1_banks` list of `sectors/semis.yaml` (Goldman
  Sachs, JP Morgan, Morgan Stanley, Bank of America, Citi, UBS).
- `action`: free-text tag (`target_change`, `upgrade`, `downgrade`,
  `initiation`).
- Threshold prereg Semis §3.5: `|target_change_pct| > 0.10` (10%).
- `target_change_pct`: signed fractional change. Calcolato come
  `(new - old) / old`. Esempio: `+0.25` per target alzato del 25%, `-0.15`
  per target abbassato del 15%.

## Curation workflow

1. Esegui ricerca temporale 2023-01-01 → 2026-04-30 per ciascuna
   categoria (vedere prereg Semis §3 per fonti raccomandate).
2. Per ogni candidate event, verifica direttamente sul press release /
   IR / SEC filing (no second-hand sources).
3. Compila la riga del CSV nel formato sopra.
4. Salva il CSV.
5. Lancia `uv run python -m catalystlab.cli build-panel --sector semis`
   per propagare nel panel.
6. Verifica che il numero di righe del panel sia aumentato come atteso.
7. Commit atomico per ogni categoria curata.
