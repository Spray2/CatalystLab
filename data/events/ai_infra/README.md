# Event log — AI Infrastructure (Step 1)

Curated event records for the 5 categories declared in
`docs/prereg_step1_ai_infra.docx` §3 and `sectors/ai_infra.yaml`.

## ⚠️ Binding constraints (prereg §11)

Before editing any file in this directory:

- **DO NOT** add events whose announcement date is after the start of data
  collection for the run in progress (anti-pattern: post-hoc event
  fishing).
- **DO NOT** modify the schema columns. The pydantic schema and the panel
  builder rely on these exact names.
- **DO NOT** add new categories or merge categories. Step 1 tests exactly
  five hypotheses (A-E); changing the count invalidates the BH correction.
- **DO NOT** edit `earnings.csv` by hand. It is regenerated automatically
  from `fetch_earnings` (yfinance + SUE computation per prereg §3.1).

## File-by-file

| File | Source | Update protocol |
|---|---|---|
| `earnings.csv` (cat. A) | auto-generated by `catalystlab.ingestion.earnings.fetch_earnings` | overwritten on each `build-panel` run; do NOT hand-edit |
| `ppa.csv` (cat. B) | manual curation from corporate press releases + Reuters/Bloomberg | append-only; one row per announcement |
| `orders.csv` (cat. C) | manual curation from SEC 8-K filings + investor relations releases | append-only; one row per announcement |
| `shocks.csv` (cat. D) | manual curation from Reuters / FT headlines | append-only; one row per macro event (sector-wide, no `ticker` field) |
| `analyst.csv` (cat. E) | manual curation from Bloomberg consensus aggregator or Yahoo recommendations | append-only; only tier-1 banks listed in `sectors/ai_infra.yaml` |

## Schema reference

### `earnings.csv` (auto)
```
ticker, announcement_date, fiscal_quarter, estimate_eps, actual_eps,
sue, has_consensus, surprise_sign
```
SUE per prereg §3.1: `(actual − estimate) / std(estimate over previous 8 quarters)`.
Threshold for event qualification: `|SUE| > 1.0`.

### `ppa.csv` (manual)
```
ticker, announce_date, counterparty, deal_mw, source_url, note
```
- `counterparty`: one of `MSFT, META, AMZN, GOOGL, ORCL` (prereg §3.2 hyperscaler list).
- `deal_mw`: optional MW size of the deal (numeric); leave blank for binary-only.
- `source_url`: REQUIRED — direct link to the corporate press release or filing.
- `note`: free text (e.g., "via subsidiary X", "framework agreement").

### `orders.csv` (manual)
```
ticker, announce_date, deal_value_usd, backlog_change_pct, source_url, note
```
- Threshold for event: `deal_value_usd > 100_000_000` OR `backlog_change_pct > 0.10` (prereg §3.3).
- One of the two magnitude fields MUST be populated; if neither, treat as binary surprise (allowed but flagged).

### `shocks.csv` (manual, sector-wide)
```
event_date, event_type, description, xlk_t1_return, source_url
```
- No `ticker` column — these are macro/sector events affecting the whole universe.
- `event_type`: short slug, e.g. `gpu_export_restriction`, `grid_blackout`, `policy_change`.
- `xlk_t1_return`: T+1 close-to-close return of XLK as magnitude proxy (prereg §3.4).

### `analyst.csv` (manual)
```
ticker, event_date, bank, action, old_target, new_target,
target_change_pct, source_url
```
- `bank`: must be one of `Goldman Sachs, JP Morgan, Morgan Stanley, Bank of America, Citi, UBS` (prereg §3.5 closed list).
- `action`: `upgrade` | `downgrade` | `target_change`.
- Threshold: `|target_change_pct| > 0.10` (prereg §3.5).

## Quality gate

Per prereg §3.1: 3 random ticker × earnings rows must be manually verified
against Yahoo Finance web before the run. Document the verification in the
commit message that locks in the panel parquet.

## Audit trail

Every commit that adds or modifies a row MUST include in the commit message:
- the source URL(s) used
- the date of curation
- a one-line rationale of why this row qualifies under the prereg definition

This trail is the audit substrate for prereg §0 (lockfile authority).
